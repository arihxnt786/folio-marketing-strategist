# Trust boundaries

The hosted entry point relies on the private Sites identity gateway. The gateway supplies the authenticated visitor ID. Every product read, write, connection, generation and join uses that visitor ID. A second brand key scopes all brand-owned operations. SQLite foreign keys cascade brand deletion. Application tables have no browser-facing database endpoint. Direct deployment behind an untrusted reverse proxy would permit identity-header spoofing. Use the supplied Cloudflare Access adapter for an independent deployment.

Mutations require a matching request Origin and an authenticated visitor. SQL uses bound parameters. Uploaded text is limited to 30,000 characters per file and rendered as text. The server limits request bodies and accepts only UTF-8 text or Markdown for brand references. The model sees excerpts as untrusted data. Its output has no tool execution capability. Human editors remain responsible for substantive claims, intellectual property and audience suitability. Source headlines provide bibliographic evidence and links rather than independent fact checking.

Each Gemini key and LinkedIn token is encrypted with AES-GCM, a random nonce and an owner-specific associated-data value. The 32-byte encryption key is a deployment secret. Rotating that secret requires reconnecting personal keys and accounts. Gemini key verification calls Google's model list. The client receives only the selected model and connection state. Personal keys are never written to local storage. LinkedIn states are brand/owner-bound, single use and expire after ten minutes. Removing a connection deletes the app's copy. Revocation at LinkedIn is a separate member action.

Brand revisions and record revisions prevent silent overwrite by a stale editor. Reapproval is required after changing copy. LinkedIn publishing acquires a durable write lock before making one POST. An ambiguous result stays in Awaiting confirmation. Check the member activity before recording a manual receipt. No automatic retry of a social post is implemented. Activity records show sanitised provider status and times. No test publishes to an external account.

Per-owner quotas cover public research, key verification, OAuth starts and AI jobs. Retriable reads have a bounded retry and deadline. Each model response is checked for shape and required properties. Restricted phrase matching is literal and case insensitive. Semantic claims and nuanced prohibited topics require human review. Model accuracy, especially with a half-billion-parameter device model, is limited.

Local development is single-user and assigns the preview identity. Never expose the development server to an untrusted network. Its SQLite file, local secrets and generated build directory are ignored by Git. The production bundle excludes the development adapter. This release has functional and isolation checks, with no independent penetration test, load certification or availability SLA.
