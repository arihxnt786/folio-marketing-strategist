# Security and operating limits

The managed deployment trusts the authenticated identity supplied by Sites, independent of whether its landing page is public. A missing identity receives HTTP 401. Independent hosting verifies Access JWT signature, issuer, audience and expiry before replacing the identity header. Never deploy the development adapter to the public internet.

Browser mutations require same-origin requests and JSON. Queries bind parameters and scope every record by owner and brand. Record updates use revisions. Provider keys use AES-GCM, random per-save nonces and owner/provider-bound authenticated data. Host secrets remain in server configuration. Keep the encryption secret stable and backed up. Legacy social connection records are inert and all LinkedIn OAuth/posting endpoints have been removed.

External excerpts, uploaded text and model decisions are untrusted inputs. Research retrieves from fixed provider endpoints and limits extraction to public matching competitor domains. The backend never executes instructions inside retrieved text. Model-selected tools pass an allowlist and response validation before dispatch. An evaluator can still miss an unsupported claim. Human review remains necessary. User-controlled strings are escaped for display and CSV formula cells are neutralized. Documents are parsed in the browser. Office readers whitelist text entries, cap expansion and reject DTDs; PDF extraction disables evaluation and processes bounded inputs. No macros are executed.

Runs have model-call, token-reservation, elapsed-time, iteration, retry and concurrency controls. A cancelled or expired lease fences stale commits. Provider services can bill a request whose response was lost. Use provider-side spending caps for a hard monetary limit. Only explicitly authorized, unexpired signed continuations can advance an existing run. Do not log keys, model prompts, authorization headers or raw provider errors. The local preview and local inference endpoint are intended for trusted development networks.

Folio has no real social media connection or automatic publishing. User and brand isolation, revision checks, budget handling and negative authentication cases are covered by the test suite. No independent penetration or sustained-load certification has been performed.

A signed-out visitor may explicitly create a seven-day test workspace. The server generates its random identity and authenticates its expiry with HMAC. Its cookie is HttpOnly, Secure and SameSite=Strict. Test identities use an isolated namespace. Test workspaces cannot configure provider keys or use deployment-wide model and paid research credentials. The server enforces creation and usage limits; expired test records are eligible for batched cleanup when another test workspace is created. Signing in opens a separate permanent workspace.
